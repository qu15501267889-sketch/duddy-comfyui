# 04 · 对 duddy-comfyui 的启发

学完这 71 个工作流，反推我们自己的工具该补什么。

---

## 一、子图必须被正确识别（当前是盲区）

**现状**：duddy 的 `canvas_state` 把画布节点原样吐出来。遇到 `14dec9cc-3745-4009-...` 这种 UUID 类型，`registry.has()` 返回 False，`precheck` 会判定「节点类型不存在」直接拦截。

**问题**：这些 UUID 是**子图实例**，不是未知节点。工作流 JSON 的 `definitions.subgraphs` 里有完整定义。

**该做的**：

```
读到 UUID 类型节点
  → 查 graph.definitions.subgraphs[id]
  → 如果是子图：标记为 subgraph，带上它的 name 和内部节点数
  → precheck 放行，不报「类型不存在」
```

同时 `duddy_canvas_state` 应该能**递归展开**子图，否则给 AI 的结构信息是残缺的——外面的 19 个节点看着像玩具，真正的算法在里面的 11 个节点。

**这条是硬伤，不修的话任何带子图的工作流都没法分析。**

## 二、Qwen 2.1 的参数规则要进知识库

现在 `precheck` 只校验「节点存在 / 参数名对 / 模型文件在」。但它管不了**参数值合不合理**：

```json
{"kind":"set_widget", "args":{"ref":"ks","widget":"cfg","value":5}}
```

这能通过预检，但 cfg=5 会严重劣化画质。

**该做的**：给 knowledge base 加一层「模型家族 → 参数建议」的规则表：

| 模型家族 | cfg | denoise | steps | 负向词 |
|---|---|---|---|---|
| Qwen-Image 2.1 | 必须 1 | 必须 1 | 25（Turbo 8） | **无效** |
| SDXL | 5-8 | 0.4-0.8 | 20-30 | 有效 |
| Flux | 3.5 | 1 | 20-28 | 基本无效 |

当计划里出现「Qwen + cfg=5」或「Qwen + 负向提示词非空」时，**给 warning 而不是放行**：

> 警告：Qwen-Image-2.1 在 cfg=1 时会跳过负向条件分支，你写的负向提示词不会生效。

这就是用户一直抱怨的「没有第一时间发现问题」的解药。

## 三、搭工作流时该学他们的结构

我们现在搭工作流是「一条龙从头连到尾」。看完这些案例，应该改成：

### 1. 参数外置

```
❌ 直接把提示词塞进 KSampler 的 widget
✅ Text 节点 → 连线 → 编码器
```

好处：用户能在画布上直接看到、改、复用。

### 2. 后处理标配

搭完主链后自动加：
- `SaveImage`（带有意义的前缀）
- `PreviewImage` 或 Compare（看结果）
- 一句 `Note` 说明这图是干什么的

### 3. 区域布局

```
左侧：模型加载（UNET/CLIP/VAE/LoRA）垂直堆叠
中间：主链路
右侧：输出
上/下：参数节点 + 说明
```

现在我们是随机坐标 `[100, 100]`，出图后画布像被炸过。

## 四、日志里那些数字，应该被自动解读

这次实测跑图，日志里有：

```
loaded partially; 1657.02 MB usable, 1503.81 MB loaded, 5864.06 MB offloaded
```

**这句话的信息量是**：显存只剩 1.6 GB，5.8 GB 模型被踢到内存，接下来会**慢到爆**。

现在 duddy 只是把日志原样吐出来。应该做一层解读：

```
检测到 OFFLOAD 严重（> 50% 模型在内存）
  → 建议：降低分辨率 或 换更小的量化版本
  → 当前 4.37MP，降到 1024×1536 可提速约 4 倍
```

用户不需要懂 `offloaded` 是什么，他需要知道**该改哪个参数**。

## 五、子图的端口顺序是隐式契约（重要认知）

子图实例的输入是按**槽位序号**接收的，没有名字：

```
subgraph[0] ← 图像块
subgraph[1] ← 掩码
subgraph[2] ← 原图
subgraph[3] ← 提示词
subgraph[4] ← 种子
...
```

意味着：
- **改一个连线就全乱**，而且不会报错，只会出烂图
- 这类工作流**无法被程序安全地自动重组**

对我自己的警示：如果 duddy 要操作一个带子图的工作流，**只改外部参数节点，绝不碰子图的输入连线**。碰了就是灾难，而且用户很难发现。

## 六、可以直接抄的三个小技巧

**① 自动 caption**
用 `TextGenerate` 让模型先描述原图，再拼进提示词。适用于任何"局部生成"场景，能显著提升一致性。

**② 原像素贴回**
重绘整个画面 → 把不该动的区域贴回原样。比指望模型"保持不变"可靠一万倍。

**③ ShowText**
提示词是拼出来的时候，**必须让用户看到最终结果**。否则 debug 全靠猜。

---

## 七、优先级

| 优先级 | 事项 | 理由 |
|---|---|---|
| P0 | 子图识别与展开 | 不修则所有带子图的工作流都分析不了 |
| P1 | 模型参数规则表（cfg/denoise/负向词） | 直接解决「AI 不懂模型」的核心短板 |
| P2 | 日志数字解读（offload / 显存） | 用户最需要「该改什么」而不是原始日志 |
| P3 | 搭工作流的布局规范 | 观感问题，不紧急 |

---

## 附：这次学到的一句话总结

> **Qwen 2.1 的编辑是「看着原图重画」，不是「在原图上改」。
> 所以 cfg 恒为 1、denoise 恒为 1、负向词永远无效。
> 想控制改动力度，靠提示词和 LoRA，不靠采样参数。**
