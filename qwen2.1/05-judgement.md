## 1. 缺陷清单：真实存在的问题

### ① cfg 用错（6 处）

```
cfg=8    Character Dataset Builder [2719177]
cfg=7.5  ComfyUI Workflows [2876940]      ×3
cfg=8    Lonecat's Simple Speed Boost Workflows
cfg=4    Qwen Image 2.1 Studio
```

这些工作流会出图，但边缘过度锐化、色彩发脏。作者大概是从 SD 工作流改的，没查过 Qwen 的官方参数。

**如果你下载了这几个，先把 cfg 改成 1 再跑。**

### ② 没有输出节点（17 个）

```
Character Dataset Creation (Flux2_Krea2_Qwen Image 2.1)
KKW Qwen 2.1 T2I
MOSS / H3 / KREA2 / QW21 / LTX25 / ideo4 Workflows
Pruna 8 steps - Qwen Image 2.1
...
```

17 个工作流里**没有任何 SaveImage / PreviewImage**。

可能是：
- 打包时漏了
- 用了第三方保存节点（但我扫的类型里没有）
- 真的是纯模板，只给你看结构

**下载这类工作流后第一件事是加一个 SaveImage，否则跑完什么都看不到。**

### ③ 负向提示词写了但无效（普遍）

21 条负向词模板，配上 90% 的 cfg=1，**全军覆没**。

这不是个别问题，是整个生态的集体误解。

## 2. 成熟度分级

按"别人拿到能不能直接用"分三级：

| 等级 | 特征 | 占比 | 代表 |
|---|---|---|---|
| **产品级** | 说明卡片 + 参数外置 + 前后对比 + 计时 + 标注 + 合理封装 | ~25% | AusBoss 全部作品 |
| **半成品** | 有说明但参数散在 widget 里，无对比无计时 | ~40% | 大部分个人作品 |
| **裸工作流** | 一堆连起来的节点，无说明，负向词抄 SD 模板 | ~35% | 匿名上传 |

**产品级的几乎全是 AusBoss 一个人的。** 这说明什么？

**说明这个生态还没形成"分享规范"。** 大多数人只是把自己的草稿扔上去。

## 3. 生态空白：没人做的事

翻遍 58 个工作流，以下**全部缺席**：

### ① 没有 ControlNet

Qwen 2.1 的 ControlNet 生态还没起来。所有工作流都是纯文本/图像条件，没有姿态、深度、边缘控制。

**这是最大的空缺。** SD 生态里 ControlNet 是标配，Qwen 这边完全没有。

### ② 没有多轮编辑

所有工作流都是**一次性指令**：你给一句话，它改一次。

没有人做"改完不满意，接着改"的循环。也没有人做"改图 → 看结果 → 再改"的交互流程。

### ③ 批量几乎为零

`batch_size` 基本都是 1。没有种子扫描、没有参数网格、没有 A/B 批量对比。

**做角色一致性时这是硬伤**——你得手动跑十次才能挑一张。

### ④ 没有种子管理

换个种子就是另一张脸。没有"锁定人脸只改背景"的机制，也没有种子库。

### ⑤ 没有质量评估

没有工作流会告诉你"这张图质量如何"。全靠人眼看。

## 4. 最佳实践：值得抄的七条

### 架构层

**① 子图封装**
把核心链路封进 subgraph，外面只暴露参数。参考 `ComfyUI Workflows`（12 节点主画布 + 141 节点子图）。

**② 参数外置成独立节点**
提示词、种子、步数、开关都单独摆出来，不要塞在采样器的 widget 里。

**③ 一个开关两条链**
用 `PrimitiveBoolean` + `ComfySwitchNode`，而不是在一条链里塞 if/else。

### 算法层

**④ 重绘后把原图贴回**
`StitchInpaint` / `TiledUpscaleStitch`。比指望模型"保持不变"可靠一万倍。

**⑤ 自动 caption**
先让模型描述原图，拼成 `指令 + " Scene: " + 描述`。temperature 0.3，seed 固定。

**⑥ 分块处理大图**
超过 2 MP 就切块，重叠带 128 px，拼回去看不出接缝。

### 使用层

**⑦ 前后对比 + 计时**
`Compare` 让用户立刻判断效果，`RunTimer` 让他知道成本。这两个节点不参与计算，但决定体验。

## 5. 反模式：看到就该警惕

| 信号 | 问题 |
|---|---|
| cfg > 3 | SD 习惯残留，会过锐 |
| denoise < 1 但 latent 是空的 | 会出半张噪声 |
| steps=8 但没挂 turbo LoRA | 会出废图 |
| 负向提示词很长 | cfg=1 下白写 |
| 主画布 > 100 节点无封装 | 打开就懵，改不动 |
| 没有 SaveImage/PreviewImage | 跑完看不到结果 |
| 提示词是标签流（masterpiece, 8k） | Qwen 按句子理解，标签效果差 |

## 6. 对 duddy-comfyui 的四个动作

### P0 · 子图识别

**现状**：`registry.has("14dec9cc-...")` 返回 False，`precheck` 判定"节点类型不存在"直接拦截。

**后果**：任何带子图的工作流都过不了预检。而这批工作流里 66 个子图。

**修法**：
```
遇到 UUID 类型
  → 查 graph.definitions.subgraphs[id]
  → 标记为 subgraph，带 name 和内部节点数
  → precheck 放行
```

同时 `duddy_canvas_state` 要能递归展开，否则给 AI 的结构信息是残缺的。

### P0 · 变量引用解析

**现状**：`GetNode("MODEL")` 的输入看着是空的。

**后果**：只看连线会误判"这个节点的输入是空的，链路断了"。

**修法**：把 `SetNode`/`GetNode` 配对解析成虚拟边。全量统计里 `GetNode -> TextEncodeQwenImage21` 有 36 次，是第二大边。

### P1 · 模型参数规则表

现在 `precheck` 只校验"节点存在/参数名对/模型文件在"，管不了**参数值合不合理**。

**加一层规则**：

| 模型家族 | cfg | denoise | steps | 负向词 |
|---|---|---|---|---|
| Qwen-Image 2.1 | 必须 1 | 1（除非 latent 来自原图） | 25/Turbo 8 | **无效** |
| SDXL | 5-8 | 0.4-0.8 | 20-30 | 有效 |
| Flux | 3.5 | 1 | 20-28 | 基本无效 |

当计划里出现「Qwen + cfg=5」或「Qwen + 负向词非空」时，**给 warning 而不是放行**。

**这就是用户抱怨的"没有第一时间发现问题"的解药。**

### P2 · 日志数字解读

实测日志里：

```
loaded partially; 1657 MB usable, 1503 MB loaded, 5864 MB offloaded
```

这句话的意思是"5.8 GB 模型在内存里，接下来会慢到爆"。但现在 duddy 只是原样吐出来。

**应该自动翻译成**：

> 检测到 78% 的模型被 offload 到内存
> 建议：分辨率降到 1024×1536，预计提速 4 倍

用户不需要懂 `offloaded` 是什么，他需要知道**该改哪个参数**。

## 7. 一句话总评

**这 71 个工作流里，真正有独立设计的只有 5 个：**

1. Tiled Upscale（分块重绘 + 接缝融合）
2. Outpaint（自动 caption + 原像素贴回）
3. Person Swap（布尔分叉 + 双 LoRA）
4. Turbo Multi-Image（多图槽位 + 子图串联）
5. Character Sheet 系列（多角度一致性）

**其余大部分是"同一个 Qwen 2.1 管线换提示词"。**

Qwen 2.1 的工作流生态还在**很早期**——大家还在解决"怎么把它跑起来"，没到"怎么把它用好"的阶段。

**这对 duddy 是机会**：把 ControlNet、批量、种子管理这些补上，做出来的工作流会比现在这些更完整。
