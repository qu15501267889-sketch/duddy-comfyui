# 05 · 生态里的其他架构手法

前四章主要基于 AusBoss 那套工作流。但 71 个工作流里还有一半来自其他作者，他们用的手法完全不同，而且**某些比 AusBoss 的更通用**。

这一章的结论来自全量统计（92 个可解析文件）：

| 节点 | 出现次数 | 用途 |
|---|---|---|
| `GetNode` | **264** | 无线取值 |
| `SetNode` | **184** | 无线存值 |
| `Fast Groups Bypasser (rgthree)` | 53 | 一键旁路节点组 |
| `ResolutionSelector` | 21 | 分辨率预设 |
| `PrimitiveStringMultiline` | 28 | 多行文本输入 |
| `MarkdownNote` | 123 | 画布说明 |
| `WorkflowGraphics` | 57 | 画布装饰 |

---

## 一、SetNode / GetNode：把画布从面条变成电路板

**这是全量数据里出现频率最高的组合（264 + 184 次），远超任何其他节点。**

### 它解决什么问题

正常连线，一个模型要连到 5 个地方，就有 5 条线横穿画布：

```
UNETLoader ─┬────────────→ KSampler
            ├────────────→ ControlNet
            ├────────────→ Upscaler
            └────────────→ 另一个 KSampler
```

节点一多，画布就是蜘蛛网，改一个参数要顺线找半天。

### 怎么用

```
SetNode（起个变量名，比如 "MODEL"）
   ↑ 接 UNETLoader 的输出

GetNode（变量名填 "MODEL"）
   ↑ 在需要的地方放一个，输出就是这个模型
```

**画布上不再有跨半屏的长线，只有「存」和「取」。** 像编程里的变量，不再用函数式嵌套。

### Eclipse 版本

统计里还有 `SetNode [Eclipse]`（82 次）/ `GetNode [Eclipse]`（76 次）——这是 Eclipse 插件提供的增强版，支持类型校验和颜色区分。两套不能混用。

### 对我们的启发

duddy 在分析工作流时必须**理解变量引用**：`GetNode("MODEL")` 不是真的输入，它的值来自某个 `SetNode("MODEL")`。如果只看连线，会误判「这个节点的输入是空的」。

**这是继子图之后的第二个分析盲区。**

## 二、Fast Groups Bypasser（rgthree）

**53 次，说明这是个刚需。**

作用：把画布上的**节点组**（group）变成一个开关面板，一键启用/禁用整组。

典型用法：

```
[组：预处理]   [组：主采样]   [组：后处理]
   ✓ 开           ✓ 开           ✗ 关
```

点一下「后处理」关掉，整组节点变灰跳过。**相当于工作流级别的 if/else。**

AusBoss 用的是 `WorkflowSwitches`（自定义节点），rgthree 这个是通用插件。功能一样，思路一致：**让用户能在不删节点的情况下切换流程**。

## 三、ResolutionSelector

官方模板里的节点，21 个工作流在用。

**它体现的是 Qwen 2.1 的参数哲学**：

```
不是设置「宽 1024 × 高 1536」
而是设置「比例 3:4 + 百万像素预算 1.0」
```

模型自己算宽高，且强制对齐到 32 的倍数。

**为什么重要**：Qwen 2.1 原生支持 2K，但"2K"是**面积**概念不是边长概念。4.0 MP 对应 2048×2048，2.0 MP 对应 1440×1440 左右。用宽高去设反而容易搞错。

## 四、MarkdownNote：41 个工作流在用

ComfyUI 原生节点，不依赖任何插件。作者们拿它做：

- 使用说明（步骤 1/2/3）
- 依赖模型清单 + 下载链接
- 更新日志
- 免责声明

**对比 AusBoss 的 `WorkflowNote`**：后者是富文本卡片（JSON 存储，带模型安装检测），好看但绑定自家插件；`MarkdownNote` 朴素但**任何装了 ComfyUI 的人都能看**。

**分享场景下，原生节点更安全。** 这也是为什么 41 个工作流选它——它们的用户可能没装 AusBoss 包。

## 五、三种「参数外置」流派对比

| 流派 | 代表 | 做法 | 优劣 |
|---|---|---|---|
| **自定义节点流** | AusBoss | `AUSBOSS_NODES_Text` / `Seed` / `Integer` / `Switches` | 好看、统一、带类型校验；**绑定插件** |
| **原生节点流** | 多数小作者 | `PrimitiveStringMultiline` / `PrimitiveInt` / `PrimitiveBoolean` | 零依赖、到处能跑；**样式朴素** |
| **无线流** | 高频大工作流 | `SetNode` / `GetNode` 传递一切 | 画布干净；**追踪麻烦**，新人看不懂 |

**没有绝对优劣，取决于分享给谁。**

- 给自己的长期项目 → 自定义节点流，效率最高
- 给公开分享 → 原生节点流，兼容性最好
- 复杂管线（>50 节点）→ 无线流，否则没法看

## 六、从「完成度」看这些工作流的成熟度

把 71 个工作流按「有没有做工程化包装」分类：

| 等级 | 特征 | 占比（估） |
|---|---|---|
| **产品级** | 说明卡片 + 参数外置 + 前后对比 + 计时 + 标注 | ~25% |
| **半成品** | 有说明但参数散落在 widget 里 | ~40% |
| **裸工作流** | 就是一堆连起来的节点，无说明 | ~35% |

**产品级的几乎全是 AusBoss 的作品。** 其他作者的很多工作流，点开就是一团节点，连提示词在哪都要找。

这说明一件事：**工作流的价值不只在算法，还在「别人能不能用」。** 一个只有作者自己能跑的工作流，分享出来意义有限。

## 七、补充：这 71 个里真正「有想法」的有几个

去掉重复版本、去掉简单换皮的，真正有独立设计的其实不多：

1. **Tiled Upscale** — 分块重绘 + 接缝融合
2. **Outpaint** — 自动 caption + 原像素贴回
3. **Person Swap** — 布尔分叉 + 双 LoRA
4. **Turbo Multi-Image** — 多图槽位 + 子图串联
5. **Character Sheet 系列**（4 个作者做了同一个东西）— 多角度一致性

**其余大部分是「同一个 Qwen 2.1 管线换提示词」。** 这也是为什么 Qwen 2.1 的工作流生态看起来热闹，但真正值得学的就那几个。

学习的时候要认准：**看结构创新，不看数量。**
